## 3. 必选算子：优化了什么（技术主线）

### 3.1 思路总览
1. **先正确后快**：suFFT 路径、host-seeded 缓冲（R7）、multi-call 护栏。  
2. **砍掉无效频谱工作**：列 FFT 截断到 `modes2`、packed trunc、pad skip-zero。  
3. **频域乘变稀疏**：gather-scatter / 双角单 launch（R11/P7）。  
4. **缓存与缩放安全**：plan/workspace/stage cache；scale 只打在 fresh buffer（P8b），禁止污染 FFT 缓存。  
5. **承认设备墙**：@256 主耗在 **irfft/C2R**；mul 已到噪声级 → 无新 SDK API 则停挖微 opt。

### 3.2 关键里程碑（可做成时间轴）

| 代号 | 内容 | 效果/备注 |
|------|------|-----------|
| R7 | host-seeded safe buffer + D2D；suFFT 指针来源合规 | chain 正确性基础 |
| R8–R11 | dual/full gather-scatter mul | 稀疏频域乘 |
| P2–P5 | 列截断、packed trunc、pad skip-zero | 大幅减 FFT 工作量 |
| P6 | col_out stage cache | 复用中间缓冲 |
| P7 | 双角点单 kernel launch | 减 launch |
| P8→P8b | 缩放位置修正（禁改缓存 FFT 缓冲） | 修 multi-call 毒化 |
| Auto-tune | 扫 path + buffer_max，落盘加载 | 加分 Skill |

正式性能演进（示意，idle）：早期 R 系列约 5.3/13.7/52 ms 量级 → P 系列截断后约 4.6/9.6/35 → **P7+P8b ≈ 3.8/8.0/29 ms**。

### 3.3 试过但封死的路（PPT「踩坑」页很有用）
- `torch.fft` @ SUPA / hybrid：谱错误  
- `BuildPlan2d`：头文件有、库未导出  
- strided pack `copy_`：D2D 崩  
- R12 手写 transpose：更慢  
- R13 ping-pong 跳过安全缓冲：污染 → rel 爆炸  
- R14 fused IN+GELU：更慢/不稳  
- P8 原地改 stage-cache：multi-call 失败  

**结论**：算子层合规高 ROI 已收割完；再挖需 SDK 新能力（2D plan / 融合 FFT）。

## 4. 选修 FNO：优化了什么

### 4.1 思路
- **公开 NS64、同一官方划分**（n_train=1000 / n_test=128）才允许 promote；768 / 自建 v2 只作旁注。  
- 有效公开集配方：scratch+continue → **hf loss + roll aug（boost）** → freeze/低 lr。  
- v2 上 width/modes 从零曾 abort；公开集仅作条件触发对照，不挡提交。

### 4.2 L2 轨迹（PPT：主报公开集 + 旁注）

**主报（公开 NS64，1000/128）**

| 阶段 | test L2 | 做法 |
|------|---------|------|
| scratch 100ep | ≈0.04353 | `train_public_ns64.py` |
| continue 50ep | 0.041835 | 中间基线 |
| boostA / boostC | 0.039612 / 0.037820 | hf+aug → residual continue |
| sq3b_freeze | 0.037520 | squeeze 平台主报（历史） |
| multistep_probe | 0.036576 | 多步 TF+soft（历史） |
| sched_samp_r2 | 0.036092 | 历史主报 |
| sched_samp_r3 | 0.035855 | 历史主报 |
| sched_samp_r5 | 0.035725 | 历史主报 · v7 |
| **freeze_r9** | **0.035302** | **当前主报 · v8**；ROUND9 |

**工程旁注（自建 v2，勿与公开分混报）**：continue3 ≈ **0.005144**（同构已 FINAL）。

### 4.3 明确失败、不再重开（除非新证据）
- multi-window 增广：test 崩到 ~0.08  
- matched per-sample loss 从零：曲线慢于 global loss  
- modes=12 / width=48 / modes=20 从零：@ep30 仍 ~0.013–0.015  
- 朴素权重平均：复数权重 cast 丢虚部 → L2 爆炸（已修脚本，未采用）

## 6. 工程方法（可讲「怎么做优化」）

1. **门禁驱动**：正确性不过不谈速度；perf 必须 idle GPU、不与重训抢 CPU。  
2. **只 promote 更优**：FNO 以官方划分 test L2 为准，失败实验保留日志不污染 demo。  
3. **单卡纪律**：f/n 不并发占 GPU；Spectral 与 FNO CPU 训可并行，但 **禁止** 并行写正式 perf。  
4. **论文启发可用则用**：TurboFNO 式 trunc/pack/scatter；F-FNO/更大 width 需重训且已用轨迹否决。  
5. **平台诚实**：设备墙写进文档，避免「假加速」数字。
